# Domain docs

This project uses a single-context layout: `GLOSSARY.md` at the repository root and architecture decision records in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the task. If they do not exist, proceed silently. The domain-modeling skill creates them lazily when terms or decisions are resolved.

## Use the glossary vocabulary

Use the glossary's terms when naming domain concepts in issues, proposals, hypotheses, and tests. If a needed concept is missing, reconsider whether it belongs or note the gap for domain-modeling.

## Surface decision conflicts

If a proposal contradicts an existing ADR, identify the ADR and explain why the decision should be reopened.
